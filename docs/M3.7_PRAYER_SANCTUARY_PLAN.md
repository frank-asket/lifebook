## Goal

A user can write a prayer concern privately, receive relevant Scripture and a short structured meditation, and come back to it later. LifeBook **supports** personal prayer; it never speaks for God, never claims to know God's answer, and never replaces pastoral care, counselling or emergency help.

## Delivery in three slices

Each slice ships on its own, so privacy-critical storage lands before any AI.

### 3.7a — Private prayer journal (no AI)

- Save, list, open, edit and delete prayers, plus "mark as answered" with an optional short encrypted note.
- Bodies encrypted with the existing envelope (context `prayer:<userId>:<id>`), so ciphertext can't be moved between users or records.
- Ownership enforced in every query (same pattern as annotations); cross-user access returns 404.
- "Delete all my prayers" in Settings; deletion is real (row delete), not soft.
- No prayer text in logs, analytics, error messages or URLs. Length cap of 5,000 characters, matching the AI stub.
- Schema: add `title?` (encrypted), `answeredAt?`, `answerNoteCiphertext?`, `updatedAt`; additive migration only.

### 3.7b — Scripture companion (deterministic, no AI)

- A reviewed library of about 25 topics (anxiety, grief, guidance, gratitude, forgiveness, waiting, illness, family, work and so on), each with 4–8 passage references.
- The user picks a topic (or several); LifeBook shows the passages, fetched live from API.Bible in KJV/Darby, plus a short reviewed reflection prompt.
- Nothing leaves LifeBook's servers. This slice is useful on its own, and it becomes the **only** passage source for 3.7c.
- The library is content, not code: stored as data, reviewed by a pastoral reviewer, EN and FR.

### 3.7c — Guided meditation (opt-in AI)

> **As built (PR #28):** the API calls OpenAI directly (`apps/api/src/prayer/openai-client.ts`), not the internal AI service with Claude. Model `gpt-4.1-mini` (override with `OPENAI_MODEL`), `store: false`, moderation plus a focused risk check before writing. The cost and caching notes below were written for Claude and have not been re-measured for OpenAI.

**Flow:** the user ticks consent for *this* prayer → API → internal AI service → Claude → structured result → stored encrypted with the prayer.

- **Scripture is never generated.** The model receives candidate passages (IDs plus text) from the 3.7b library and returns only **IDs**. LifeBook then inserts the verified text from API.Bible. This rules out misquoted or invented verses.
- **Structured output** (`output_config.format`, JSON schema):
  `{ passages: [id] (1–3, from candidates), reflection (≤120 words), questions: [string] (2–3), guided_prayer (≤100 words, first person, addressed to God), safety: "none" | "concern" | "crisis" }`
- **Model:** `claude-opus-5-5` (current default; $4 / $20 per million input/output tokens, cache reads $0.20), effort `low` to start, adaptive thinking (always on for this model). Refusal fallback enabled (`fallbacks: "default"`), and `stop_reason` checked before reading the result.
- **Prompt caching:** the system prompt (voice, theology guardrails, output rules) and the candidate library come first and are cached; the prayer text comes last.
- **Estimated cost:** about 3k input tokens (mostly cached) and 0.5–1k output tokens, so roughly **2–4 cents per meditation**. Measure with real usage before setting limits. Per-user cap to start: 5 meditations per day.
- **Minimum data sent:** prayer text and chosen language only. No name, email, user ID, profile or history. The request ID is random and not linked to the user anywhere outside LifeBook's database.
- **Retention:** before launch, confirm the Anthropic organisation's current data-retention terms and whether zero data retention is available for this use, and state it plainly in the consent copy.

### Safety

- **Crisis screen before generation.** If the prayer (or the model's `safety` field) indicates risk of self-harm, harm to others or abuse, LifeBook shows a calm, non-judgmental message with **local crisis contacts** (configurable by country) and encourages contacting someone now. It does not generate a meditation for that prayer. The prayer itself stays private and is not escalated or shared.
- **Voice guardrails** in the system prompt and in the eval: no "God is telling you…", no promised outcomes (healing, provision), no medical, legal or financial advice, no judgement of the user's faith, and gentle encouragement toward community or pastoral care where fitting.
- **Evaluation before launch** (done: 68 cases, see M3.7_MEDITATION_EVAL.md): about 60 synthetic prayers (EN/FR) covering ordinary concerns, grief, doubt, anger at God and crisis wording. Graded against the guardrails, with crisis recall as a hard gate (every crisis case must be caught). A pastoral reviewer signs off on outputs.

## Acceptance criteria

1. Prayers save, list, edit, delete and "delete all" for a signed-in user; they persist across sign-ins; plain text is absent from the database and logs (same checks as the M3.6 staging run).
2. Account B cannot read, change or delete account A's prayers or meditations (404).
3. The topic companion shows only reviewed passages, in EN and FR, with attribution.
4. Guided meditation runs only with per-prayer consent; quoted Scripture always matches API.Bible exactly; output follows the schema and word limits.
5. Every crisis case in the eval shows crisis contacts and no generated meditation.
6. Nothing works without consent, and turning consent off stops new AI processing immediately.
